{# Top-of-app announcement banners (Settings > Banners, v3 parity). Included from BOTH navs (the header exists twice - project rule). Vanilla JS: the navs render before jQuery loads. Text is rendered with textContent (admin-authored, but escaping is not optional) and the level picks a colour through a fixed map - a stored value never reaches a style attribute. Dismissal is a per-browser-session convenience (sessionStorage, guarded: some contexts throw on access). The strips go at the top of the content scroller (.main-panel > .content), not of .main-panel: .main-header is position:fixed over the top of .main-panel and .content clears it with its own margin-top, so a strip placed before .content sat UNDER the header and pushed the page down by its height plus that margin. A flex .content (the 403 page's centred layout) would lay a strip beside the page, so nothing renders there. First frame (2026-10-30): includes/top_strips.html calls mount() with the active rows the server already read, while the page parses; the fetch runs only on a page that did not (anonymous, a failed read, no hook). #}
