Guest Portal

How war-room guests reach this instance from outside. The portal agent container runs the Cloudflare tunnel in the mode chosen here and reports its status; only the guest portal is ever exposed through it.
Agent key not configured. Set PORTAL_TUNNEL_AGENT_KEY in .env (the same value the tunnel container gets) and recreate app; until then the agent cannot read these settings and links fall back to this instance's own address.
Tunnel mode
Setting up the named tunnel in Cloudflare Zero Trust
  1. Networks → Tunnels → Create a tunnel → Cloudflared. Name it (for example iris-guest-portal) and copy the token from the install command (the long string after --token).
  2. On the tunnel's Public Hostname tab add your hostname (for example rooms.example.com) with service HTTP → nginx:8081. That is the portal-only server block; nothing else in IRIS-NG is reachable through it.
  3. Paste the token and the public URL below and save. The agent switches within about 15 seconds; the status card confirms the connection.
  4. Recommended: Access → Applications → self-hosted application on that hostname with a one-time-PIN policy for the domains you invite. Guests then confirm their email before the portal even loads.
Base URL guests use. Required for a named tunnel; leave empty for a quick tunnel (the agent reports the random hostname). Invitation links and room addresses are built from it.
Write-only: never shown again. Leave blank to keep the stored token; type clear to remove it.
